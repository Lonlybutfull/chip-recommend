# Hermes 单 Skill 全芯片开放网络任务设计

## 1. 背景

现有 Hermes 开放网络链路要求同时指定一个 Skill 和一个目标芯片。它适合验证“一个芯片 + 一个 Skill”，但不能表达新的任务入口：**Skill 必选，芯片可选；未指定芯片时，一次任务覆盖当前数据库中的全部芯片，并同时发现新芯片和新 URL。**

旧的 `run_open_web_all_skills.py` 虽能枚举全部芯片，但由 Python 固定模板、关键词和全局前 10 条规则编排，不是 Hermes 按 Skill 决策，不能作为新主链路。

## 2. 目标

1. 一次运行只选择六类中的一个 Skill。
2. `target_chip` 改为可选：
   - 有值：执行单芯片定向任务；
   - 无值：创建一个父任务，在同一次运行中处理芯片快照里的全部芯片。
3. 全量任务还必须运行开放发现单元，用于发现数据库中尚无记录的新芯片和新 URL。
4. Skill 不只描述字段，还要完整规定搜索词生成、工具调用、URL 判断、选择 JSON、关联任务和异常处理步骤。
5. Hermes 负责决策和流程推进；工具只执行搜索、去重、访问、快照、校验和记录。
6. 当前阶段所有结果只进入隔离测试区，不修改正式数据库。

## 3. 非目标

- 本设计不恢复自动心跳或定时巡检。
- 本设计不自动发布字段到正式数据库。
- 本设计不在一次父任务中自动执行关联出的其他 Skill；只记录后续任务建议，避免跨域递归失控。
- 本设计不再维护旧的关键词粗筛为 Hermes 主链路降级方案。模型或工具失败必须显式记录。

## 4. 任务入口

新的后端入口接受：

| 参数 | 要求 | 含义 |
|---|---|---|
| `skill` | 必填 | `chip-identity`、`chip-specs`、`chip-compute`、`chip-compatibility`、`chip-benchmark`、`chip-deployment` 之一 |
| `target_chip` | 可选 | 指定时只处理该芯片；省略时处理全部芯片 |
| `target_fields` | 可选 | 省略时使用 Skill 的全部字段 |
| `mode` | 当前固定 | `test`，仅写隔离运行目录 |

全量任务启动时读取一次正式数据库，保存去重后的芯片名称快照。运行过程中正式库即使变化，也不改变本轮任务集合，保证统计可复现。

## 5. 一次全部处理的含义

“一次全部处理”指一个父运行从启动到结束覆盖全部芯片，不需要人工分批重新启动。内部可以拆成子任务，以控制上下文和支持失败重试，但这些子任务属于同一个 `session_id`：

```text
父任务：chip-specs / 全部芯片
├─ 芯片单元：A100
├─ 芯片单元：H100
├─ 芯片单元：昇腾 910B
├─ ...数据库快照中的全部芯片
└─ 开放发现单元：发现新芯片和未收录 URL
```

父任务只有在所有芯片单元和开放发现单元都进入终态后才结束。单个芯片失败不终止整轮；系统在本轮内自动重试，重试耗尽后记录为失败，父任务最终标为 `partial`。

## 6. 单个芯片单元的流程

每个芯片单元严格执行同一份已选 Skill：

1. Hermes 加载 Skill，并读取芯片名称、目标字段和已有 URL 摘要。
2. Hermes 按 Skill 生成恰好 10 条互不重复的搜索词及理由。
3. Hermes 调用 `open_web_search`；工具执行搜索、安全检查、URL 规范化，并同时对本轮结果和已有链接库去重。
4. Hermes 将全部候选 ID 交给 `open_web_preview`；工具检查可访问性、保存完整快照，并返回每页不超过 500 字的核心文本。
5. Hermes 阅读全部预览，为每个候选返回选择或拒绝、理由、匹配信息类别和建议关联 Skill。
6. Hermes 调用 `open_web_submit_selection`；工具校验选择 JSON，并对选中页面按当前 Skill 提取字段和原文证据。
7. 系统校验字段白名单、值、单位、芯片归属和证据原文，记录通过与拒绝结果。
8. 系统记录 URL 资产、发现它的 Skill、搜索词、选择理由、信息类别、字段证据和关联 Skill。

Skill 必须把第 2～8 步的业务规则写清楚；工具名称和 JSON 合同保持统一，六个 Skill 只改变领域规则。

## 7. 开放发现单元

只枚举已有芯片无法发现新芯片。每个全量父任务额外创建开放发现单元：

1. Hermes 根据当前 Skill、厂商目录和已有芯片覆盖情况生成不绑定具体芯片的搜索词。
2. 搜索结果与本轮候选、已有链接库统一规范化和去重。
3. Hermes 根据 Skill 判断页面是否包含目标信息，并从页面中识别芯片名称。
4. 已存在的芯片结果合并到对应芯片单元；未存在的芯片作为“新芯片候选”记录。
5. 新芯片候选只进入隔离结果，不直接创建正式芯片记录。

## 8. Skill 内容要求

六个 Skill 都必须具备以下章节：

1. 使用场景与目标字段；
2. 单芯片和开放发现两种搜索词生成规则；
3. 来源优先级和禁止来源；
4. 搜索工具调用步骤；
5. URL 预览、选择和拒绝标准；
6. `UrlDecision` JSON 示例；
7. 正文提取规则和证据要求；
8. 其他信息类别识别与关联 Skill 规则；
9. 无结果、不可访问、模型失败和重试规则；
10. 完成条件与禁止事项。

Skill 不直接发起 HTTP、写数据库或操作文件；这些动作只能由受限工具完成。

## 9. 状态和持久化

父任务新增整体统计：

- `total_chips`
- `completed_chips`
- `succeeded_chips`
- `partial_chips`
- `failed_chips`
- `search_queries`
- `unique_urls`
- `reachable_urls`
- `selected_urls`
- `validated_facts`
- `new_chip_candidates`
- `linked_tasks`

每个芯片单元单独保存状态、10 条搜索词、候选 URL、预览、决策、字段和工具轨迹。父任务使用检查点记录已完成单元；进程重启后从未完成单元继续，而不是重新搜索所有芯片。

## 10. 并发和边界

- 对用户表现为一次完整任务，内部使用有限并发执行芯片单元。
- 默认并发数由服务器配置控制，不由 Skill 或页面传入。
- 搜索和模型调用遇到限流时指数退避；单芯片重试次数有上限。
- 不再使用“所有芯片共享全局前 10 个 URL”的规则。每个芯片都必须获得自己的搜索、预览和选择结论。
- 同一个规范化 URL 可以服务多个芯片或 Skill，但网页快照只抓取一次，其他单元复用快照并分别保留决策记录。

## 11. 页面展示

状态页只展示人类需要的父任务结果：

1. 当前 Skill 和运行范围（全部芯片或指定芯片）；
2. 总芯片数及完成进度；
3. 搜索词、去重 URL、可访问 URL、选中 URL、有效字段数量；
4. 按芯片查看最终 URL、选择理由和提取字段；
5. 新芯片候选和关联 Skill；
6. 失败芯片及简明原因。

工具级调试轨迹保留在运行产物和 API 中，不默认铺满页面。

## 12. 完成条件

全量父任务完成必须满足：

1. 芯片快照中的每个芯片都有终态；
2. 每个成功芯片单元都完成搜索、预览、URL 决策和字段校验，或者明确记录“未找到有效 URL”；
3. 开放发现单元完成并记录新芯片候选；
4. 所有 URL 和字段都可追溯到搜索词、Skill、网页快照和证据；
5. 正式数据库前后指纹一致；
6. 推荐、搜索、画像和现有 API 回归测试通过。

## 13. 迁移策略

1. 保留现有单芯片 Hermes 入口，先把 `target_chip` 协议改为可选。
2. 在其上增加父任务和芯片单元调度，不复制第二套搜索/提取逻辑。
3. 增加开放发现单元和跨单元 URL 快照复用。
4. 更新六个 Skill，使其包含完整第 2～8 步。
5. 更新状态 API 和页面展示。
6. 在隔离测试中先运行一个 Skill 的全芯片任务，验证完整性、恢复能力和正式库指纹。
7. 旧 `run_open_web_all_skills.py` 继续只作为对照回归工具，不再作为线上全量入口。

## 14. 验收标准

- 不传 `target_chip` 可以启动一个 Skill 的全芯片任务。
- 一次启动覆盖任务开始时的全部芯片，不需要人工分批。
- 不存在全局前 10 个 URL 截断。
- Hermes 为每个芯片执行 Skill 定义的搜索、预览和 URL 选择流程。
- 开放发现能记录至少“未命中新芯片”或具体的新芯片候选结论，而不是静默跳过。
- 中断后可以从检查点继续。
- 页面能回答：处理了哪些芯片、每个芯片选择了哪些 URL、提取了什么、为什么失败。
- 全部结果只在隔离区，正式数据库未变化。
