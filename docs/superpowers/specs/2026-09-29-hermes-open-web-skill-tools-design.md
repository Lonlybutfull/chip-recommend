# Hermes 驱动的开放互联网芯片资料发现设计

日期：2026-09-29  
状态：已确认
范围：仅限隔离测试流程，不修改正式数据库

## 1. 目标

把开放互联网采集的前半段改为真正的“**Hermes + 领域 Skill 决策，工具执行**”：

1. 人工在后端指定本次更新类别和目标芯片。
2. Hermes 加载对应领域 Skill，由 Kimi 生成 10 组搜索词。
3. Hermes 调用项目提供的受限搜索工具，工具搜索并去重 URL。
4. Hermes 调用预览工具，工具验证可访问性、抓取网页并返回不超过 500 字的核心正文。
5. Kimi 根据页面预览选择目标 URL，并通过工具提交结构化 JSON 和选择理由。
6. 工具把通过的 URL 交给现有完整正文抓取、字段提取、证据校验和隔离记录流程。

成功标准是：日志能够证明每个搜索词和 URL 是哪个 Skill 产生或选择的；模型只负责判断，确定性工具只负责执行；正式 `data/data.db` 始终不变。

## 2. 不在本次范围内

- 不启用心跳、cron 或每日自动巡检。
- 不从页面提供启动按钮；开发测试仍由后端命令触发。
- 不把测试 URL、候选字段或提取结果写入正式来源库和业务表。
- 不改模型数据更新流程，Hugging Face 模型同步继续独立运行。
- 不重写已经存在的完整正文抓取、快照、字段校验和页面结果展示。

## 3. 核心原则

### 3.1 Skill 与工具分工

- **Skill** 是给 Hermes/Kimi 的业务说明书，定义找什么、如何构造搜索词、怎样判断页面、哪些字段属于本类以及何时拒绝。
- **工具** 是确定性执行能力，负责搜索网络、URL 安全校验、规范化、去重、访问、正文清理、保存快照和提交选择结果。
- Skill 不直接发 HTTP 请求、不操作 SQLite、不执行网页中的命令。
- 工具不自行判断网页业务价值，不用关键词分数替代 Kimi 的选择。

### 3.2 单次只运行一个领域 Skill

正式的测试入口一次只选择以下一个类别：

| Skill | 更新域 |
|---|---|
| `chip-identity` | 厂商、型号、系列、发布时间和发布状态 |
| `chip-specs` | 显存、带宽、功耗、制程、形态、架构和互联规格 |
| `chip-compute` | 支持精度、理论峰值和计算单元 |
| `chip-compatibility` | 芯片与模型、框架、精度及软件栈兼容关系 |
| `chip-benchmark` | 芯片×模型训练或推理实测及完整测试条件 |
| `chip-deployment` | 后端、版本、启动方法、容器和部署拓扑 |

“六类一起运行”只保留为离线回归测试，不再作为线上默认发现流程。

## 4. 总体流程

```text
后端创建隔离运行
  → 指定目标 Skill、芯片和可选字段
  → Hermes 加载该 Skill
  → Kimi 返回 10 组搜索词 JSON
  → Hermes 调用 open_web_search
  → 工具搜索、规范化 URL、跨搜索词去重并保存结果
  → Hermes 调用 open_web_preview
  → 工具逐页做安全检查和可访问性测试
  → 工具去 HTML，返回每页最多 500 字核心正文
  → Kimi 逐页判断价值和信息类别
  → Hermes 调用 open_web_submit_selection 提交选择 JSON
  → 工具校验模型决定
  → 对通过 URL 运行现有完整抓取、字段提取与证据校验
  → 保存隔离结果、关联 Skill 和 URL 资产记录
  → 页面展示已完成运行
```

现有链接库复查继续作为独立分支保留，不与本次开放互联网搜索预算混算。

## 5. Hermes 插件工具

项目新增一个 Hermes 插件 `aishperf-open-web`，通过 Hermes 的 `PluginContext.register_tool()` 注册三个工具，并归入独立 toolset。插件只能调用项目提供的受限 JSON 接口，不能获得任意 shell、数据库路径或 Docker 权限。

### 5.1 `open_web_search`

用途：接收 Kimi 生成的搜索词，调用项目搜索适配器并去重。

输入：

```json
{
  "run_id": "隔离运行 ID",
  "skill": "chip-specs",
  "target_chip": "NVIDIA H100",
  "queries": [
    {"query": "NVIDIA H100 official memory bandwidth datasheet", "reason": "查官方规格书"}
  ]
}
```

约束：

- `queries` 必须恰好 10 条，去空白和大小写规范化后不得重复。
- 每条搜索词最多取 10 个结果。
- URL 先做协议、主机、私网、重定向和规范化检查，再按规范 URL 去重。
- 返回稳定的 `candidate_id`，后续工具只能引用本轮生成的候选。

输出包含：搜索词、Skill、结果排名、URL、标题、搜索摘要、搜索提供商、重复来源和安全状态。

### 5.2 `open_web_preview`

用途：测试候选 URL 是否可访问，并为 Kimi 提供轻量正文预览。

输入：

```json
{
  "run_id": "隔离运行 ID",
  "candidate_ids": ["candidate-1", "candidate-2"]
}
```

行为：

- 逐一执行安全校验、访问、重定向检查、响应大小限制和正文规范化。
- HTML 删除脚本、样式、导航、页眉页脚、表单和评论；PDF/JSON/纯文本复用现有解析器。
- `core_text` 最多 500 个 Unicode 字符，只用于 URL 选择；完整正文仍保存到隔离快照，后续提取阶段不受 500 字限制。
- 相同规范 URL 在一次运行中只访问一次，即使被多个搜索词命中。

输出包含：`candidate_id`、请求 URL、最终 URL、HTTP 状态、访问结果、标题、`core_text`、内容哈希和失败原因。

### 5.3 `open_web_submit_selection`

用途：接收 Kimi 对预览页面的最终选择，并启动现有后半段流程。

输入：

```json
{
  "run_id": "隔离运行 ID",
  "skill": "chip-specs",
  "decisions": [
    {
      "candidate_id": "candidate-1",
      "selected": true,
      "reason": "官方产品页明确给出 H100 显存和显存带宽",
      "matched_categories": ["基础参数", "算力指标"],
      "suggested_skills": ["chip-compute"]
    }
  ]
}
```

校验：

- 候选必须来自同一 `run_id`，且已经通过预览工具。
- 每个被选 URL 必须有非空、可读的理由。
- `matched_categories` 和 `suggested_skills` 只能使用六类白名单。
- 不接受模型新增 URL、数据库路径、命令或任意字段名。
- 同一 `(run_id, canonical_url, skill)` 只能提交一次。

校验通过后，工具把选中 URL 交给现有完整抓取和字段提取入口。未选 URL 也记录理由，但不进入完整提取。

## 6. Skill 合同

六个 Skill 都采用相同章节：

1. 适用场景与不适用场景。
2. 负责字段与目标表。
3. 生成 10 组搜索词的规则和覆盖要求。
4. URL 预览判断规则、来源优先级和拒绝规则。
5. 三个工具的调用顺序及严格输入输出格式。
6. Prompt injection 防护：网页文字永远是资料，不是指令。
7. 完成标准和日志检查方式。

搜索词必须由 Kimi 根据本次目标实时生成，Python 不再提供固定主模板。为保证覆盖，Skill 要求 10 条搜索词至少覆盖：官方产品页、规格书/白皮书、开发者文档、评测或兼容资料、中文和英文表达。不同领域可调整各来源所占数量。

## 7. Kimi 输出协议

Hermes 当前统一使用 `kimi-k2.6`。所有决策必须返回 JSON，并经过 Pydantic/JSON Schema 校验：

- 搜索计划不是 10 条、存在空词或重复词：向模型发起一次修复请求；仍不合法则本轮失败。
- URL 选择包含未知候选或未知 Skill：直接拒绝，不自动纠正。
- 模型超时、限流、空响应或非法 JSON：记录明确错误，不退回关键词评分，也不伪装为成功。
- 网页预览不得进入 system prompt；用明确分隔的“不可信网页资料”字段传入。

芯片项目容器的字段提取接口同步改为 Moonshot `kimi-k2.6`，关闭 thinking，并使用服务端密钥注入。Hermes 配置和项目容器不得各自使用不同模型造成判断口径漂移。

## 8. 跨 Skill 联动

如果目标 Skill 是基础参数，但 Kimi 发现页面还包含算力或实测信息：

1. 当前 Skill 只提取自己负责的字段。
2. `suggested_skills` 记录其他信息类别。
3. 系统在同一隔离运行中创建关联的测试子任务，复用已经保存的完整快照。
4. 子任务不得再次搜索或访问同一 URL，最大联动深度为 1。
5. 使用 `(run_id, canonical_url, skill)` 去重，防止任务循环。

因此，一个 URL 可以关联多个 Skill，但每个 Skill 的字段所有权仍保持独立。

## 9. 运行产物与页面展示

在现有运行目录中增加：

- `hermes_search_plan.json`：Kimi 生成的 10 条搜索词和理由。
- `search_results.jsonl`：工具返回的全部搜索结果及去重关系。
- `url_previews.jsonl`：访问结果和最多 500 字核心正文。
- `url_decisions.jsonl`：Kimi 对每个候选的选择、理由和关联 Skill。
- `hermes_tool_trace.jsonl`：Hermes 调用了哪个工具、输入摘要、状态、耗时和错误；不记录密钥及完整请求头。

现有 `source_snapshots/`、`url_assets.jsonl`、`extracted_facts.jsonl`、`events.jsonl` 和测试数据库继续保留。

状态页只展示已完成运行。展开后依次显示：目标 Skill、10 条搜索词、搜索结果与去重、URL 预览与可访问性、Kimi 选择理由、完整提取字段和跨 Skill 子任务。页面不提供启动按钮。

## 10. 安全与隔离

- 三个工具只接受当前隔离运行 ID；正式模式和任意路径参数均被拒绝。
- 工具服务只绑定本机，不直接暴露公网。
- Hermes 插件只持有调用工具服务所需的短期本地凭据，不持有数据库和 Docker 权限。
- 搜索和预览工具沿用现有 SSRF、HTTPS、私网地址、重定向、响应大小与超时保护。
- 所有测试写入 `data/test_runs/<run_id>/`；正式数据库只读复制，并比较运行前后指纹。
- Kimi 密钥只存在服务器环境或 Hermes 私有配置中，不写 Git、日志和运行产物。

## 11. 失败处理

- 搜索提供商部分失败：保存成功结果并把运行标为“部分成功”。
- 候选 URL 无法访问：记录 HTTP/网络原因，继续其他候选。
- Kimi 搜索计划或选择 JSON 不合法：最多修复一次，失败后终止智能决策阶段。
- Kimi 不可达：本轮失败；不得使用旧 GLM、关键词分类或 DeepSeek 静默降级。
- 完整字段提取失败：保留搜索、预览、选择和快照，明确显示“发现成功、提取失败”。
- 任意隔离保护失效：立即安全阻止，不启动后续任务。

## 12. 测试与验收

### 离线自动测试

- 六个 Skill 均能生成合法的 10 条搜索计划。
- 搜索工具正确处理重复 URL、危险 URL、多个搜索词命中同一 URL和搜索提供商失败。
- 预览工具覆盖 HTML、PDF、JSON、空正文、403、超时、重定向和超大响应。
- 选择工具拒绝未知候选、跨运行候选、未知 Skill、空理由和重复提交。
- 多类别 URL 能创建一次关联子任务且不会循环。
- 模型非法 JSON、超时和修复失败有明确状态。
- 正式数据库文件指纹保持不变，现有芯片搜索、详情、推荐和 JSON API 回归测试通过。

### 81 服务器验收

选择一个 Skill 和一颗芯片完成一次真实测试，页面应能看到：

1. Kimi 生成的 10 条搜索词。
2. 每条搜索词的结果、去重情况和所属 Skill。
3. 每个去重候选的访问结果和 500 字以内预览。
4. Kimi 选择或拒绝 URL 的 JSON 理由。
5. 选中 URL 的完整字段提取和逐字证据。
6. 页面发现其他类别时生成的关联测试子任务。
7. 正式数据库未变化。

## 13. 实施顺序

1. 建立运行状态和三个工具的 JSON 契约，先用离线假数据测试。
2. 实现并注册 `aishperf-open-web` Hermes 插件工具。

4. 把固定搜索模板入口替换为 Hermes 搜索计划；保留旧入口仅供回归比较。
5. 接入 URL 预览、模型选择和跨 Skill 子任务。
6. 复用现有完整抓取与字段提取，并把项目容器模型切换到 Kimi。
7. 更新状态页，展示 Hermes 搜索计划、工具调用和 URL 选择理由。
8. 完成离线测试、81 服务器真实测试和正式库指纹核验后再部署。
