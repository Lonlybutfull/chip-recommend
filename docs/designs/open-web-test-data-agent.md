# Design: 开放互联网芯片信息采集测试流程

Generated by /office-hours on 2026-09-21
Branch: codex/recommendation-vram-ui
Repo: bupt-lxc/chip-recommend
Status: PARTIALLY IMPLEMENTED — 六类 Skill 与隔离测试主链路已落地；真实模型复测和容器级安全加固仍是后续验收项
Mode: Builder

## Problem Statement

当前数据智能体主要从已有 URL 或种子页面的链接中寻找更新目标。下一阶段需要保留这条旧链路，同时新增“按信息类别主动搜索开放互联网”的测试链路：先确定要补充的信息类别，调用对应 Skill 搜索候选 URL，再经过粗筛、网页访问和精确复核，提取候选信息并记录 URL 资产。

本阶段只验证流程和数据质量。现有 Skill、搜索得到的 URL、提取结果和候选数据都只能进入隔离测试区，不能修改正式数据库 `data/data.db`，不能启用 Hermes 心跳或定时任务。

## What Makes This Cool

系统不再被动等待已有链接变化，而是能够围绕“缺什么数据”主动寻找网页。更重要的是，每次测试都会留下搜索词、候选 URL、淘汰原因、网页镜像、提取证据和信息类别，后续可以明确看出系统为什么找到这个网页、为什么信任或拒绝它。

## Constraints

- 只允许代码层面手动触发，不启用心跳、cron 或 systemd timer。
- 正式数据库在执行前后必须保持文件哈希一致。
- 每次运行创建独立目录：`data/test_runs/<run_id>/`。
- 测试数据只能写入该目录下的测试数据库和 JSON 运行产物。
- 模型更新不进入本流程，继续走独立 API 与代码更新。
- 兼容、实测、部署是三类不同信息，使用不同 Skill、字段和目标表。
- URL 与信息类别是多对多关系，一个网页可以同时包含多类信息。
- Agent 不直接写正式业务表；抓取、安全检查、去重、快照和测试由确定性脚本完成。
- 新 Skill 使用独立的 `TEST_SKILL_REGISTRY`，不注册到正式调度器、Hermes 配置或正式 Publisher。
- “删除模型 Skill”仅表示测试运行时过滤，不删除或改写现有正式功能。
- 搜索摘要、网页正文和模型输出都视为不可信输入，不允许其中的指令触发命令、跳转或写库。

## Premises

1. 不为每个 Skill 重复实现完整爬虫，而是由所有 Skill 共用搜索、抓取、快照、去重、日志和测试工具。
2. Skill 负责定义“找什么、如何判断、提取什么、怎样校验”，脚本负责稳定执行。
3. 开放互联网采集不是无限爬站，而是有搜索预算、有优先级、有停止条件的受控发现。
4. 所有实际访问页面都进入本次 URL 资产记录；只有精确复核通过且有原文证据的页面才标记信息类别和可用字段。本阶段不晋升到正式来源库。

## Recommended Approach

采用“共享采集引擎 + 分类 Skill 合同”。现有 `DataAgentOrchestrator` 继续负责运行周期和任务队列，`SourceRefresher` 继续负责网页访问、重定向安全检查和快照，测试工作区继续提供数据库隔离。新增共享的开放互联网搜索阶段，并重构 Skill 分类和页面显示。

### 总体流程

```text
人工选择本次要找的信息类别
  → 先生成目标字段清单
  → 对应 Skill 按类别词、来源类型和目标字段生成搜索计划
  → 搜索开放互联网
  → 第一阶段粗筛：只看 URL、标题、摘要和域名
  → 抓取高分候选网页并保存网页镜像
  → 第二阶段复核：确认网页确实包含目标信息
  → 按 Skill 提取候选数据和原文证据
  → 格式、范围、实体和来源校验
  → 写入本次隔离测试区
  → 运行现有搜索、画像、推荐、API 和 JSON 兼容测试
  → 记录 URL、父 URL、搜索词、信息类别和判定结果
```

### 第一批 Skill

| 页面名称 | 内部 Skill | 负责内容 |
|---|---|---|
| 芯片型号 | `chip-identity` | 厂商、型号、系列、发布时间和状态 |
| 基础参数 | `chip-specs` | 显存、带宽、功耗、形态、制程等参数 |
| 算力指标 | `chip-compute` | 支持精度及不同精度的最大算力 |
| 兼容信息 | `chip-compatibility` | 是否支持某模型、框架、精度或软件栈 |
| 实测数据 | `chip-benchmark` | 芯片、卡数、输入输出、并发、吞吐和时延 |
| 部署资料 | `chip-deployment` | 推理后端、软件版本、启动参数、拓扑和部署说明 |

价格和生态数据可以作为第二批 Skill。删除本流程中的 `model-catalog` 与 `model-activity` 调度。

“删除”仅指从本次测试任务清单中过滤；现有模型更新代码和正式功能保持不动。

### Skill 与数据边界

| Skill | 预期业务数据域 | 允许处理的内容 | 不允许混入 |
|---|---|---|---|
| 芯片型号 | `chips` | 厂商、型号、系列、发布时间、发布状态 | 性能猜测、模型资料 |
| 基础参数 | `chips` | 显存容量、显存带宽、功耗、制程、形态、架构、互联参数 | 实测吞吐、理论算力 |
| 算力指标 | `chips` | 支持精度、各精度理论峰值、计算单元 | 实测结果 |
| 兼容信息 | `chips` 或 `chip_model_compatibility` | 通用框架/软件栈支持写入 `chips` 候选；明确到模型的兼容关系才生成 `chip_model_compatibility` 候选 | 吞吐和时延数值 |
| 实测数据 | `chip_model_benchmarks` | 芯片、模型、卡数、输入输出、并发、吞吐、时延和测试条件 | 厂商理论峰值 |
| 部署资料 | `deployment_guides` | 当前表只映射芯片、模型、后端、来源 URL、标题和简要备注；版本、命令、拓扑和完整步骤保留在测试记录中 | 仅声称“兼容”但没有部署内容的页面 |

每个 Skill 文件必须固定版本，并声明目标表、允许字段、实体键、搜索词模板、来源优先级、证据要求、校验规则、预算和通俗拒绝原因。Skill 只能生成候选结果，不能获得正式数据库写权限。

本阶段不会把候选数据写入测试副本里的正式业务表。运行时仅在测试副本创建 `test_extracted_records` 和 `test_url_classifications` 两张临时表，保存完整 JSON、预期目标表、证据和验证结果；它们不加入正式 `schema.sql`。这样可以测试搜索、提取和校验，而不会让测试结果看起来像已经进入系统。将来如果设计“正式晋升”，再单独定义业务表映射、去重与 `field_provenance` 写入规则。

### 每个 Skill 的统一合同

每个 Skill 只需要回答六个简单问题：

1. 本次要找什么信息？
2. 应该使用哪些搜索词？
3. 哪些来源优先？
4. 怎样判断网页是否有用？
5. 从网页中提取哪些内容？
6. 什么情况下拒绝结果？

内部可继续保存字段白名单、JSON Schema、来源级别和阈值，但页面不直接展示这些技术名称。

### 两阶段 URL 判断

第一阶段只使用搜索结果元数据，成本低、覆盖面大：

- 输入：URL、标题、摘要、域名、搜索词。
- 输出：可能包含的信息类别、相关实体、可信来源等级、是否值得访问、简短原因。
- 作用：从大量结果中选出少量候选，不做字段提取。

第二阶段基于真实网页镜像进行复核：

- 输入：最终 URL、网页正文、表格、元信息和必要的上下文。
- 输出：是否包含目标信息、包含哪些类别、对应哪些芯片、可提取字段及逐字段原文证据。
- 作用：阻止标题党、登录页、失效页、搜索结果页和无数据的宣传页进入提取阶段。

网页文本只作为待分析资料，不作为 Agent 指令。模型仅能返回预先定义的 JSON Schema；网页中的“运行命令”“读取凭据”“忽略规则”等内容一律作为普通文本处理。

### 测试执行器与搜索入口

本阶段不通过 Hermes 心跳或 cron 执行，新增一次性命令 `scripts/run_open_web_test.py`。它每次只创建一个隔离测试工作区，然后依次调用搜索、抓取、复核、提取和测试模块；退出后不会自行再次运行。

81 服务器上的执行入口仅保留在后端。控制进程使用 SQLite Backup API 将正式库一致性复制到 `<run_id>/data.db`，后续链接、分类和候选字段只写该测试副本与运行目录。状态页只负责展示结果和刷新记录，不提供启动控件。

语义判断使用可配置的 OpenAI 兼容模型接口，模型名、地址和密钥均来自服务器环境变量。密钥、Cookie 和请求头不得进入日志或运行产物。调用必须设置超时、有限重试、并发上限和严格 JSON Schema；模型不可达时本次运行标为“部分成功”或“失败”，已抓取网页仍留在测试区，不能落入正式库。

搜索层定义统一 `SearchProvider` 接口，输入为搜索词、页数和语言，输出统一的 URL、标题、摘要、排名和来源。首版测试实现使用 DuckDuckGo HTML 适配器，但所有请求仍经过共享 URL 安全与响应限制；若服务阻断或页面结构变化，明确显示“搜索服务不可用”，不把空结果解释为“没有资料”。后续接入正式搜索 API 时不改 Skill。

### 开放互联网链接的充分获取

搜索不依赖单一关键词，而是由 Skill 生成有限的查询矩阵：

```text
信息类别 × 厂商/芯片实体 × 来源类型 × 时间范围
```

来源优先级：

1. 厂商官网、产品页、规格书和官方文档。
2. 官方开发者文档、官方 GitHub、云平台产品文档。
3. MLPerf、论文、会议材料和公开评测报告。
4. 可信技术媒体和社区实测，只用于补足官方缺失信息。

每个 Skill 设置搜索预算和停止条件，例如：抓取前 20 个搜索结果、精确访问最多 10 个页面；连续两轮没有新增高质量 URL 时停止。高质量列表页或文档中心可以在测试区标记为候选种子，下一次测试继续验证，但不会写入正式来源库。

首版默认预算按“一次运行”计算：最多 30 个搜索请求、每个 Skill 最多 20 个去重后候选、每个域名最多 5 个候选、全局最多访问 40 个网页、下载 100 MB、模型输入 20 万 tokens。去重在计入访问预算前完成；达到任一上限立即停止新增任务，并在页面显示触发了哪个上限。

首版同时支持 HTML、纯文本、JSON 和 PDF。PDF 上限 20 MB，只做文本与表格抽取，证据记录页码；图片扫描 PDF 标记为“发现资料，但暂不能读取”，不会被当成无关网页。

### URL 测试资产记录

每次运行在 `data/test_runs/<run_id>/` 中保存：

- `search_queries.json`：目标字段，以及按类别关键词、来源类型和目标字段生成的搜索计划。
- `url_candidates.jsonl`：搜索结果、粗筛分数和淘汰原因。
- `url_assets.jsonl`：所有实际访问 URL 的发现链路、访问结果和复核结论；复核通过时额外记录一个或多个信息类别与提取字段。
- `source_snapshots/`：抓取的原始页面和规范化正文。
- `extracted_facts.jsonl`：提取结果及逐字段证据。
- `data.db`：从正式库复制的隔离测试数据库，只用于兼容性测试。
- `test_report.json`：正式库哈希、测试库变化、回归测试结果和失败原因。
- `manifest.json`：代码提交、配置摘要、Skill/Schema/解析器/模型版本、运行预算和所有产物哈希。
- `events.jsonl`：持续追加的阶段事件，进程异常退出时也能恢复已完成步骤。

URL 资产至少记录：URL、父 URL 或来源搜索词、网页名称、所属信息类别、涉及芯片、来源类型、首次发现时间、最后访问时间、访问结果、内容哈希和判定原因。

另外记录搜索提供商、结果排名、规范 URL、完整重定向链、抓取状态、Skill 版本、模型与提示版本哈希、校验规则、通俗拒绝原因，以及证据所在页码、表格单元格或正文片段位置。同一规范 URL 在一次运行中只抓一次，但可以关联多个 Skill。

所有 JSON 和 JSONL 均包含 `schema_version`。`events.jsonl` 采用单运行文件锁和逐行追加；写入新 manifest 时先写临时文件、校验后原子替换。恢复时忽略最后一条不完整 JSONL 记录并从最后一个已完成任务继续。

### 正式库零写入保护

测试命令必须同时满足以下条件才能启动：

1. 数据库路径位于 `data/test_runs/<run_id>/data.db`。
2. 运行目录存在由测试工作区生成的 `test_mode.json`。
3. 模式固定为 `test`，API 和脚本不接受 `formal`。
4. 正式库只允许用 SQLite 只读 URI 打开；写入连接工厂拒绝空路径、正式库绝对路径、目录逃逸、符号链接和硬链接。
5. 控制进程使用 SQLite Backup API 创建一致性副本后立即关闭正式库连接；测试 worker 容器不挂载正式 `data/` 目录，只保留测试目录写权限。所有写入接口都必须接收本次运行的 `workspace_id`，没有合法测试工作区标记时直接拒绝。
6. 正式 `data/data.db`、`data/data.db-wal` 和 `data/data.db-shm` 在复制前和 worker 退出后记录文件身份、存在状态和 SHA256；哈希只作为审计证据，不作为主要隔离边界。若服务器上同时有正常业务写入，则报告中标记“存在外部变化”，但不能归因于测试 worker。
7. 使用独立 `TestRecordWriter`，它只认识 `test_extracted_records` 和 `test_url_classifications`；测试进程不导入、不初始化也不调用正式 `CandidatePublisher`。
8. 无论任务成功、失败、超时或被中断，都执行正式库哈希复核并生成测试报告。

这里采用多层保护：路径限制负责防止误配置，只读连接负责阻止误写，哈希校验负责发现保护失效。不能仅依赖页面上的“测试模式”按钮或一个布尔参数。

### 页面边界

状态页不提供信息类别、芯片、搜索词、口令或“开始测试”等启动控件。开发测试由后端在收到明确测试请求后执行；页面只展示运行结果、提取信息、访问过的网页、执行记录和刷新入口。技术字段和 JSON 保留在展开详情中，不在首屏堆叠。

### 失败与恢复

阶段状态统一为：`等待 / 进行中 / 完成 / 部分成功 / 失败 / 已取消 / 安全阻止`。搜索限流、网络失败、登录页、验证码、危险重定向、响应过大、模型超时、非法 JSON、证据不匹配、实体歧义、来源冲突、磁盘不足、人工取消和进程崩溃都必须留下通俗原因与技术详情。

每个搜索、抓取和提取任务使用稳定任务 ID，重试时复用已经保存的搜索结果和网页快照。`events.jsonl` 每完成一步就追加，`manifest.json` 保存恢复点；重复启动同一运行时只能续跑，不能重复写入。

## Existing Components Reused

- `chip_model/pipeline/data_agent.py`：运行周期、任务队列、Skill 路由和测试模式。
- `chip_model/pipeline/source_refresh.py`：URL 安全检查、网页抓取、重定向处理和快照。
- `chip_model/pipeline/candidate_validation.py`：实体、字段格式和范围校验。
- `chip_model/pipeline/test_workspace.py`：隔离数据库副本与测试标记。
- `chip_model/pipeline/run_history.py`：按运行记录过程和结果。
- `static/run-history.js`：展示本次运行卡片和详情。

需要替换或调整的部分：开放互联网搜索入口、Skill 分类、兼容与部署拆分、模型 Skill 调度、正式模式入口以及页面文案。

所有调整先放在测试专属命令、注册表和页面入口中，不替换正式任务入口。测试 API 在独立子进程和随机本地端口启动，必须显式传入测试数据库路径；测试模式中缺少 `db_path` 时直接失败，不能回退到全局默认库。

## Planned Acceptance Criteria

- 后端可以指定信息类别、芯片和目标字段，在 81 服务器上启动一次测试。
- 测试能记录搜索词、粗筛结果、访问结果、网页镜像、复核结论和提取事实。
- 同一 URL 不重复抓取，并可标记多个信息类别。
- 兼容、实测和部署分别进入正确的测试数据结构。
- worker 对正式库路径和 Docker socket 的访问探针必须失败；正式库哈希一致时记录“审计通过”，若哈希因外部业务写入而变化则记录“发现外部变化、需人工核验”，不能自动归因于测试 worker。
- 故意把正式库路径传给写入接口时，任务在写入前被拒绝并留下清晰日志。
- 测试报告明确显示成功数、失败数、淘汰原因和数据保存位置。
- 所有现有测试与新增隔离测试通过。
- 固定离线样本覆盖正常网页、重复 URL、多类别 URL、坏 JSON、无证据、危险 URL、超大响应和 PDF；真实互联网只作为可选 smoke test。
- 空数据库路径、伪造标记、目录逃逸、符号链接、硬链接、遗漏 `--db`、并发启动和中断恢复都必须有失败路径测试。
- 容器内访问正式库路径和 Docker socket 必须失败，代码目录写入探针必须失败，测试目录写入探针必须成功。
