# 数据抓取运行卡片与字段变更对比

## 目标

每次独立启动的抓取周期展示为一张卡片。一次周期中的父页抓取、URL 发现、详情页抓取、领域提取、候选校验和发布是卡片内部的阶段，不拆成互不相关的运行。

当前问题：接口默认只读取 latest_test_db，历史隔离会话不可见；前端分别请求最新来源抓取和最新智能体状态，来源记录只覆盖部分阶段；不同隔离数据库中的周期 ID 会重复；候选只有新值与证据，缺少旧值及旧来源。

## 方案选择

采用同页历史运行卡片，按开始时间倒序排列。卡片摘要常驻，详细内容按需加载；最新运行默认展开，其他运行折叠。相比独立详情页，这种方式能直接比较前后几轮；相比按每个 Worker 作业各建卡片，能保留一次运行的完整因果链。

## 卡片内容

1. 标题与摘要：会话标识、周期 ID、测试/正式模式、父页或来源名称、开始/结束时间、耗时、状态、成功/失败/等待任务数、候选/已发布字段数。
2. 运行参数：来源列表、选择范围、数量上限、重试次数、深度限制、提取领域、模型和推理设置等。只展示实际记录的参数；旧记录缺失时显示“未记录”，不能用当前默认值冒充历史值。敏感凭证不记录、不返回。
3. 流程：来源规划 → 首轮访问 → URL 发现 → 第二轮访问 → 字段提取与校验 → 待审核/发布。每阶段显示未执行、执行中、成功、部分失败或失败，并说明输入和输出。
4. URL 链路：父 URL、发现任务、目标 URL、最终响应 URL、HTTP 状态、访问时间和失败原因。首轮与第二轮来源记录归入同一张卡片。
5. 字段变更：按实体展示字段名、运行基线值、基线来源、候选新值、新来源、原文证据、置信度、审核/发布状态。支持新增、变化、值相同、旧值未知的分类。
6. 时间线与任务明细：合并本周期及其关联抓取阶段的事件，按时间排序；展开查看 Worker、尝试次数、错误和提取结果。保留日志下载或结构化 JSON 入口。

## 字段语义

- “计划提取字段”来自本轮任务的领域和字段范围，仅表示可能检查的字段，不表示一定更新。
- “候选变更”来自 extraction_candidates，显示预计变更的具体实体和字段。
- “实际更新”只以 candidate_publications 和 field_provenance 中的发布记录为依据。
- 已发布候选的旧值优先取发布时保存的 old_values，避免错误地拿发布后的当前值作旧值。
- 未发布候选的基线值优先取隔离副本的运行基线；正式周期需保存候选形成时的旧值与旧来源快照。无法恢复的历史值标“未记录”，可另列当前值作为参考并明确其时间语义。
- 多个候选竞争同一字段时逐条保留来源与状态，不静默覆盖。
- “证据存在于原文”和“证据足以支持结论”分开说明，候选通过机械校验不等于已审核正确。

## 后端实现边界

- 新增运行列表与单次运行详情查询，测试模式遍历受信任 test_runs 下有合法标记的会话，支持分页。
- 使用“模式 + 会话标识 + 周期 ID”定位运行；客户端不能传任意数据库文件路径。
- 详情查询只聚合该周期关联的任务、发现边、source_checks、events、candidates、publications，禁止混入其他周期记录。
- 为新运行保存可审计的参数快照，为候选保存旧值及来源信息。历史数据只读取兼容，不捏造或回填无法证明的历史参数。
- 对缺表、旧版本数据库、损坏会话和不存在的运行返回明确状态；单个坏会话不阻断全部历史列表。
- 保留现有查询接口兼容性；单独模块负责运行聚合，避免继续堆积 server.py。

## 前端与刷新

使用独立运行卡片替换目前混合的“最新一次执行 + 智能体 + 全局日志”区域，保留系统总览和手动运行入口。刷新更新各自卡片，保留展开状态；不存在任务时显示明确空状态。耗时对运行中任务动态计算，对已结束任务固定。待发布显示“候选待审核/发布”，不暗示发布器已启动。

## 验收

- 两个隔离会话都含周期 #1，仍分别显示，不串日志或候选。
- 同一次两轮任务的 1 个父页和 2 个详情页全部出现在同一卡片。
- 现有两轮测试会话可查看 3 个候选的基线值、来源和新值；没有来源时如实标缺失。
- 已发布候选、空候选、提取失败、截断响应、运行中任务和无历史运行均有对应状态。
- 新增后端回归测试先验证运行隔离和字段旧值语义，再实现接口；最后以浏览器验证历史卡片、展开、刷新和安全转义。
- 使用本地可写副本运行验证，不发布任何业务候选，不修改原始只读数据库。
