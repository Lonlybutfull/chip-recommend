# 数据抓取智能体设计与实施路径

## 1. 目标

把现有一次性爬取脚本升级为由 Hermes 周期触发、可增量执行、可自动写入并可由人类全程追踪的数据更新系统。最终覆盖芯片、模型、芯片×模型适配、实测、部署和价格数据。

参考材料中的字段划分和 Skill 流程可直接吸收，但结合当前项目做三点调整：

- 保留现有 Hermes 每天北京时间 02:00 的调度，不改为材料示例中的 08:00。
- HuggingFace 继续作为现有模型数据主链路；ModelScope 可作为后续补充来源和活跃度来源。
- 不设置阻塞式人工审批。明确、官方且通过全部测试的变化自动写入；无法唯一确认的变化自动拒绝。人类负责监控、追溯和事后纠正。

## 2. 总体结构

```text
Hermes 心跳
  → 更新协调器：选择本轮到期任务、控制并发和预算
  → 种子/列表页首轮访问：提取真实 outbound_links
  → URL 发现 Skill：筛选、规范化、去重并创建目标清单
  → 详情页同周期二轮访问：保存快照后再进入领域提取
  → 数据 Skill：芯片目录 / 基础规格 / 算力 / 互联 / 生态 / 价格 / 模型
  → 共用工具：URL 去重、条件请求、快照、正文提取、实体匹配、单位校验
  → 候选事实：字段值 + 原文证据 + 来源 + 提取版本
  → 校验与影子库测试
  → 单一 Publisher 串行写库 + field_provenance
  → 运行轨迹、差异和更新结果展示
```

Agent 负责来源发现、页面语义理解、实体判断和冲突分析；Skill 固化字段范围、来源优先级、刷新周期与拒绝规则；Python 脚本负责抓取、缓存、哈希、解析、校验、去重、事务写入和测试。多个采集任务可以并行，但 SQLite 正式写入必须串行。

## 3. Skill 划分

第一批建议按数据所有权拆分，而不是按网站拆分：

| Skill | 负责内容 | 建议周期 |
|---|---|---|
| `chip-catalog` | 新芯片清单、身份、生命周期、官方入口 | 1～2 周 |
| `chip-basic` | 显存、带宽、功耗、形态、PCIe | 每月或来源变化时 |
| `chip-compute` | 支持精度、Dense/Sparse 峰值算力 | 每月或来源变化时 |
| `chip-interconnect` | 卡间互联、带宽、Scale-up/Scale-out | 每月 |
| `chip-ecosystem` | 推理/训练框架、软件栈、模型支持 | 2～3 天 |
| `chip-price` | 官方价、渠道价、云租赁价 | 2～3 天 |
| `model-catalog` | 模型身份、分类、参数、上下文、能力 | 每周增量 |
| `model-activity` | 下载、收藏、趋势和热门模型集合 | 每天或每周 |
| `benchmark-ingest` | 芯片×模型推理/训练实测 | 每两周 |
| `deployment-ingest` | 适配状态、引擎、版本和部署文档 | 每周 |

每个字段只能有一个主责 Skill。其他 Skill 发现越界信息时写入跨 Skill inbox，不直接修改对方字段，避免重复抓取和冲突覆盖。

## 4. 单次任务流程

1. 协调器按 `next_check_at`、优先级和失败退避选择任务。
2. 共用抓取器用 URL、ETag、Last-Modified 和正文哈希判断是否需要重新解析。
3. 种子页或列表页首轮访问时，脚本在清洗正文前提取真实 HTTPS 链接；`url-discovery` 只能从该清单筛选相关详情页，不能猜测地址。
4. 服务端规范化 URL、去跟踪参数、去重、检查公网地址和抓取深度，并在同一周期发起详情页第二轮访问。
5. 原始响应和规范化正文以内容哈希保存，同一网页只抓取一次，供多个 Skill 复用。
6. 详情页形成可信快照后，确定性解析器先提取结构化字段，Agent 只处理非结构化语义；新页面读取完整快照，已更新页面只读取新增差异。
7. 产出候选事实，必须包含实体、字段、值、单位、原文证据、来源 URL、时间和提取器版本。
8. 执行实体唯一匹配、字段格式、合理范围、来源等级、旧值冲突和跨字段校验。
9. 在影子数据库执行同一写入，并测试芯片搜索、画像、系统状态、推荐候选和 JSON 兼容性。
10. 全部通过后备份数据库，由 Publisher 在一个事务中写入主表和 `field_provenance`；否则自动拒绝。

## 5. 人类监控

“系统状态 & 数据更新”作为统一观察入口：

- 最近运行：开始/结束时间、状态、耗时、成功、失败和变化数量。
- 运行轨迹：按时间显示选源、访问 URL、HTTP 状态、响应大小、快照、差异、候选字段、校验、影子测试和发布。
- 来源明细：原始 URL、重定向后 URL、尝试次数、错误和下次检查时间。
- 变化审计：新旧正文差异、候选字段、修改前后值、备份位置和溯源写入数量。
- 运行中的任务每 5 秒自动刷新；历史记录可按 run_id 追溯。

运行日志采用结构化表 `update_run_events`，而不是只写文本文件。这样网页、API、Hermes 通知和后续告警都能复用同一份数据。

## 6. 当前已经实现

第一版完整技术闭环已经落到代码中：

| 模块 | 实现 |
|---|---|
| 周期调度 | `DataAgentOrchestrator` 创建周期、按 Skill 周期选择来源并生成去重任务 |
| 共享抓取 | 同一 URL 每轮只由 `SourceRefresher` 抓取一次，保存原始与规范化快照 |
| 两轮发现 | 首轮提取真实链接，Hermes 筛选目标；服务端去重、安全校验并在同周期二次访问 |
| 增量判断 | ETag、Last-Modified、正文哈希、到期时间和失败退避 |
| 模型同步 | 已知模型通过 HuggingFace API 增量更新，规格与活跃度复用一次响应 |
| 并行 Agent | 原子领取和租约机制允许不同 Skill Worker 并行，过期租约自动释放 |
| Skill 路由 | 依据来源分类和字段所有权路由到 10 个领域 Skill |
| 跨域消息 | `skill_inbox` 将越界信息交给字段主责 Skill，并复用已有快照 |
| 解析去重 | `parse_ledger` 按链接、Skill、内容哈希和解析器版本防止重复解析 |
| 候选事实 | 保存实体键、字段、值、单位、原文、来源、置信度和状态 |
| 实体去重 | `entity_aliases` 提供全 Skill 共用别名；别名冲突时拒绝 |
| 安全发布 | 支持芯片、模型、实测、兼容和部署；先影子测试，再备份、事务写入和溯源 |
| 人类监控 | 状态页展示任务、候选证据、inbox、发布、备份及日志，并自动刷新 |
| Hermes 接入 | 完整 gate、受限 SSH claim/finish/publish 桥接和 ForceCommand 白名单 |

主要入口：

```bash
python scripts/run_data_agent.py run --limit 50
python scripts/run_data_agent.py status
python scripts/run_data_agent.py claim --worker worker-1 --skills chip-basic,chip-compute --limit 5
python scripts/run_data_agent.py finish --job-id 123 --worker worker-1 --status succeeded --result result.json
python scripts/run_candidate_publisher.py --candidate-ids 10,11,12
```

Agent 返回的每个事实必须包含目标表、实体键、字段、值、单位、逐字段原文证据、HTTPS 来源、来源类型和置信度。成功结果先进入 `ready_to_publish`，不会因为 Agent 声称成功就直接修改数据库。

## 7. 上线与运营顺序

### 阶段一：小范围上线

先在 10～20 个官方链接上运行完整周期，观察一周的失败率、页面变化噪声和候选准确率，再扩大来源数量。

### 阶段二：扩大芯片数据覆盖

逐步把目录、基础规格、算力、互联、生态和价格来源纳入定时范围，按覆盖率和失败率调整周期。

### 阶段三：扩大模型与关系来源

在现有 HuggingFace 增量同步之外补充 ModelScope 活跃度，并持续增加 benchmark、兼容和部署来源。

### 阶段四：质量运营

持续进行新实体发现、非官方证据升级、失效链接、重复实体和冲突治理。

每次扩容或修改数据前都必须运行现有 API、搜索、画像、算力推荐、数据库完整性和 JSON 兼容测试，避免数据、代码或文档变化破坏原有功能。
