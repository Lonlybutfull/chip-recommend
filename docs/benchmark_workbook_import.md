原始文件：`推理测试明细数据_20260713.xlsx`。导入时校验 SHA-256，防止把后来修改的工作簿误认为同一版来源。

## 导入与保存

```bash
python scripts/import_benchmark_workbook.py --dry-run
python scripts/import_benchmark_workbook.py
```

`benchmark_workbook_rows` 逐行保存所有 20 个工作表的 881 个非空行，包含原始单元格、公式、工作表与行号、来源链接；推理、适配、能耗、对比、MTP 的原始数据不会因当前解析器尚未识别而丢失。可识别的 720 条推理观测中，717 条作为工作簿记录写入 `chip_model_benchmarks`，另外 3 条固定参考场景由导入脚本自动调用独立的核验导入器，避免重复。字段变更写入 `field_provenance`。重复执行不会重复插入。

结构化字段包括芯片、模型、物理卡数、输入/输出 token、并发、输出吞吐、TTFT、TPOT、部署条件；没有可靠证据时保留空值或“待核实”标记。其他原始指标留在 `cells_json` 和 `metrics_json`。对比页的数据可能与单芯片压测页重复，因此保留原始记录但不凭对比页重复计算芯片分数。

## DeepSeek-V4-Flash 排序

“适配性测试”页将部分芯片压测关联到 Flash；其“整机输出吞吐 ÷ 单卡输出吞吐”可核验相应测试使用的卡数。独立工作表标题明确写出的 4/8 物理卡优先于该比值。来源证据与置信度记录在 benchmark 的 `notes` 和字段级溯源中。

当前推荐只使用 **1024 输入、1024 输出、1 并发** 的同模型记录。先把整机输出吞吐除以物理卡数；同一芯片若有多个部署/量化配置，使用单卡吞吐、TTFT、TPOT 各自的中位数，不挑最快一条。实测项按单卡吞吐 60%、TTFT 20%、TPOT 20% 评分，再以全局 60% 权重参与推荐；无可比实测的芯片在该项统一得中性分，不用其他模型或其他输入并发的压测冒充 Flash 实测。

本版固定参考条件有 7 款芯片可计算分数。H200 的具体形态未在表内确认，因此虽然原始记录已保存，暂不映射到 H200 SXM/NVL 的其中一款。其他测试场景已入库，但尚未按用户任意输入/输出/并发动态匹配排序。

工作簿与数据库在本地导入。服务器若要获得相同结果，需安装新增的 `openpyxl` 依赖、传入同一版工作簿并在服务器数据库执行上述导入命令；仅部署代码不会自动带上这些本地数据。
