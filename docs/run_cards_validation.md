# 独立运行卡片实施与验证

已实现后端会话级历史查询、独立运行卡片、字段旧值/候选新值及来源对比。

## 使用

打开 `/status`，在“独立运行记录”中展开任一卡片。每张卡片按会话标识和周期 ID 定位，包含流程阶段、参数、计划字段、候选对比、两轮 URL、全部轮次访问、子任务、时间线和 JSON 下载。每页 10 次运行，可翻页。自动刷新与页面重载会保留展开状态。

新接口：

- `GET /api/v1/data-agent/runs?mode=test&limit=10&offset=0`
- `GET /api/v1/data-agent/runs/{session}/{run_id}`

正式模式的会话标识为 formal；隔离会话必须位于当前数据库相邻 test_runs 下且具有有效 test_mode.json，不能指定任意数据库路径。旧接口仍保留。

## 字段与参数的时间语义

- 新候选在 finish 的同一事务中保存旧值和来源快照；旧隔离数据库按需增加 candidate_baselines 表。
- 已发布字段优先读取发布记录中的 old_values，避免把写入后的值当旧值。
- 历史候选没有快照时，只展示“当前库参考值 · 历史旧值未记录”，不伪造历史基线。
- 值相同、填补空值、值变化与未知分别标注。候选未发布明确显示“尚未写入业务表”。
- 新周期记录实际 limit、force、max_attempts、代理是否启用、深度限制和来源 ID，不记录代理凭据。
- 历史外部 Worker 的参数没有记录时显示“未记录”。对会话内已有的受限诊断文件，仅提取实际响应的模型名、token 计数与调用事件，不返回请求密钥或完整原始响应。
- 未启动发布器，状态“候选待审核/发布”不代表正在自动发布。

## 验证证据

- 完整 pytest：160 passed（新增旧隔离库兼容回归前）。
- 新回归覆盖：同号周期跨会话隔离、拒绝路径穿越、单个坏会话隔离、来源阶段聚合、候选快照稳定性、发布旧值优先、API 历史查询、模型日志凭据过滤、旧隔离库快照兼容。
- Playwright 实测现有 4 个独立会话，最新周期展示 2 条发现链路、3 次网页访问、3 个字段对比。
- 实际模型响应展示 kimi-k2.6，7 次已记录响应、116258 tokens（历史调用计数，不是本次界面验证产生的调用）。
- 验证同时展开两张卡片、静默刷新、整页重载后展开状态保留；JSON 下载只包含所选运行。
- 无 JavaScript 页面错误；390px 手机宽度无页面横向溢出，字段表局部可横向滚动。
- 本地服务继续使用可写 baseline.db；没有发布任何候选，也未修改原始只读 data/data.db。
