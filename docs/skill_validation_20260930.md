# 六类开放互联网 Skill 验证记录

## RED：无新版规则时的基线表现

压力场景同时包含维护窗口、全量 1098 颗芯片、全局前 10 URL 捷径和跨类别信息取舍。独立代理虽然选择保留完整流程，但出现了三处偏差：

- 误解“芯片可选”，认为基础参数不能省略目标芯片；
- 将开放发现的新芯片动态加入本轮队列，破坏冻结范围和可靠续跑；
- 自行发明 `domain`、`chip_id`、`reviewer` 等字段，没有遵循三个工具的精确 JSON 合同。

## GREEN：新版 `chip-specs` 复测

读取新版 Skill 后，同一代理能够准确说明：

- Skill 必选；芯片省略时是“全部已有芯片 + 一个开放发现单元”；
- 每个芯片单元独立生成 10 条搜索词，不使用全局前 10 URL；
- 三个工具严格按搜索、预览、提交顺序执行；
- 开放发现只记录候选，不回填本轮芯片队列；
- 提交 JSON 使用 `run_id`、`unit_id`、`scope_type`、`skill` 和完整 `decisions`；
- 失败只重试当前单元，耗尽后留痕并继续其他单元。

## 自动化合同验证

`tests/test_open_web_skill_contracts.py` 对六个真实 Skill 逐一检查：中文触发描述、负责字段、全量/单芯片范围、开放发现、工具顺序、精确 JSON 字段、跨 Skill 建议、一层联动、重试和安全边界。

完整回归结果：`316 passed`。
